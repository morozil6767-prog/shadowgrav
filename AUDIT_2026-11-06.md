# Source audit and engineering update — 2026-11-06

## Executive assessment

This is already a substantial numerical-simulation project, not a small prototype. The repository contains a binary64
force engine, finite-sphere saturation, pair-exact force terms, an adaptive HEALPix non-additive overlap correction,
velocity modes, a velocity-Verlet/fixed-point integrator, conservation/physics diagnostics, a brute-force reference path,
independent Python oracles, a large Rust test suite, and a native egui instrument. The sky map and force arrows were already
implemented before this patch; they are not merely TODOs.

The strongest earlier result is the repository-reported Certified test (c) screening measurement: about 4.31e-7 error at
tau_c=20, about 64.8 million leaves and zero cap hits for the prescribed three-sphere collinear geometry. This is a strong
benchmark result, but it is *one geometry and one observable*. It does not certify arbitrary overlap configurations,
all diagnostics, V2, all background-extinction regimes, or the complete model as a scientific theory. The evidence ledger
in `shadowgrav-core/TRACEABILITY.md` explicitly retains partials and gaps.

**Overall judgement:** strong research-code foundation; not yet a fully evidenced, world-class research platform. The
largest remaining risks are (1) spec/addendum governance, (2) missing or partial verification rows, (3) lack of fresh
multi-OS execution results, and (4) lack of a captured native desktop UI proof.

## Changes made in this update

### Core validation and failure handling

- Added `Particles::validate()` for structure-of-arrays length agreement, finite positions/velocities, positive finite stored mass/density, unit-mass probes, and admissible finite body species offsets.
- Added `Globals::validate()` and `Options::validate()` for calibration, velocity, background extinction, quadrature configuration and preview-mode gates. Both `derive()` and `evaluate_forces()` call the validators before indexed computation.
- Strengthened `Derived::validate_shape()` to reject inconsistent arrays and non-finite/non-physical derived values.
- Added `SimConfig` checks for `eta_E` in [0,1] and `zeta` equal to 0.5 or 1.
- Added `World::validate()` and invoke it before stepping, before adaptive step selection and from construction. This catches direct mutation of public arrays/configuration (for example `diag_every = 0`) before it can cause indexing faults or a modulo-by-zero panic.
- Added checked acceleration construction so finite force divided by a tiny mass cannot silently create a non-finite initial acceleration.
- Added negative regression tests in `shadowgrav-core/tests/hardening.rs`.

### Geometry and stress tests

- Added exact two-body translation and rotation equivariance, central-force direction and reciprocity checks.
- Added a six-occluder collimated geometry that exercises a genuinely non-additive correction while keeping physical spheres separated; it checks overlap activation and finite forces.
- These tests are authored source changes; they have not been executed in this environment.

### UI and export

- Trail rendering now flushes visible polyline segments when a trail point crosses behind the perspective camera plane; it no longer connects separated visible sections.
- Force arrows now use the local differential of the 3D view's perspective transform, retaining foreshortening and off-axis perspective instead of using a simple orthographic projection.
- Added mass to `BodyView`, resolving a source-level mismatch where the export code requested a mass field that the UI snapshot type did not provide.
- Export schema `shadowgrav.snapshot.v2`: numeric rectangular CSV with a stable 27-column header, plus a `.meta.json` sidecar containing the column dictionary, code-unit map, run identity, parameters, diagnostics, per-target and per-pair metrics, quadrature health, validity flags and conformance reasons.
- Fixed a UTF-8/data-model bug in metadata reason partitioning: `badge_n_red` is an entry count, so the vector is split by entry count rather than by a byte index. The export unit test includes a quote, newline and Unicode caveat.

### CI and evidence capture

- Expanded `.github/workflows/ci.yml` so core tests and UI build/tests run on Ubuntu, macOS and Windows.
- Added locked builds, uploaded test/build logs, weekly CI runs and a scheduled certified test (c).
- Added `scripts/local-proof.sh`, `scripts/local-proof.ps1` and `MACHINE_PROOF.md` for machine details, test/build outputs, native UI launch and screenshot checklist.
- Updated out-of-date core/UI verification docs that previously said the engine/UI was not implemented or had never been compiled. Historic evidence tags remain identified as historic in `TRACEABILITY.md`.

## What is still not demonstrated

1. **No local Rust execution in this audit.** This environment has no `rustc` or `cargo`, and the Rust toolchain download endpoint was unreachable. The changed Rust source, tests, UI export, and workflow have therefore not been compiled or executed here.
2. **No native UI screenshot.** A real desktop session is needed. The new machine-proof scripts capture launch logs, but a person must inspect the window and save the actual screenshots.
3. **No live multi-OS CI results.** The workflow is now configured; the repository must be pushed and green Actions artifacts collected for the exact commit.
4. **Not every frozen-spec diagnostic is closed.** See the Partial/Gap rows in `shadowgrav-core/TRACEABILITY.md`. Examples include the alpha_bg>0 momentum-balance check, an uncalibrated-mode numerical readout test, direct saturation-diagnostic and overlap-heating cross-checks, and several optical-depth/Seeliger/reference diagnostic assertions.
5. **V2 and overlap accuracy remain scope-limited.** The repository ledger calls parts of V2 first-order-reference coverage partial; the sky view intentionally shows static geometry rather than shifted V2 discs. The certified screening accuracy applies to the specified collinear test, not arbitrary geometries.
6. **The PDF and numerical addenda need formal agreement.** `ADDENDUM2.md` proposes a 0.01 instead of 0.1 adaptive `h*gamma` cap and a modified fixed-point residual denominator; `integrator.rs` implements those proposals. The uploaded frozen PDF specifies the original 0.1 cap and `|v^(i+1)| + 1e-30` denominator. Until the addendum is formally adopted, report this as a deliberate deviation from the uploaded contract. `derive.rs` also evaluates the truncated A(tau) series through tau<1 rather than the PDF's tau<0.05 threshold; this choice should remain in the numerical error budget.

## Recommended path to a world-class research instrument

1. **Freeze a single governing contract.** Version the PDF and accepted addenda together. Every departure (integrator stopping rule, adaptive cap, series threshold, quadrature refinement) must be explicitly approved and linked to tests.
2. **Close the traceability ledger.** Turn each Partial/Gap row into a test with a stated oracle and tolerance. Prioritize alpha_bg momentum balance, overlap heating/D-bar, tau_max and Seeliger pairing, delta_EP, V2 first-order and the full geometry-oracle matrix.
3. **Make geometry coverage systematic.** Generate parameterized test families over angular separation, impact parameter, radius ratio, depth ordering, optical depth, interior/contact offsets and background extinction. Compare production HEALPix to the independent all-rays/reference oracle and report convergence curves and cap hits, not just pass/fail.
4. **Benchmark reproducibly.** Record CPU, OS, Rust version, compile flags, thread count, particle count, overlap density, leaves/s, target/s, wall time and memory. Keep serial and parallel results separate. Do not market the thin-fast preview as the conforming engine.
5. **Capture real release evidence.** Run local proof scripts on the target desktop, capture the checklist screenshots, push the updated workflow, and retain per-OS Actions artifacts under the tested commit hash.
6. **Build scientific trust.** Publish model assumptions, limitations, numerical error budgets, reference scripts, test data and negative results. A numerically correct implementation validates the specified model's computation; it does not validate the model's physical truth. Claims about nature require independent empirical and theoretical validation.
